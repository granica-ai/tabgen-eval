# Failure modes

The catalogue of failure modes TabGenEval is designed against — *statistical* ones, where the metric computes but could mislead, and *engineering* ones, where messy inputs could break the code. Each entry has at least one covering test; `tests/test_traceability.py` is a meta-test that fails CI if any mode loses its coverage (or if a referenced test is renamed/deleted), and its `COVERAGE` map is keyed by the failure-mode IDs below.

Input misuse raises an actionable error. Valid but degenerate data retain computable results and factual diagnostics. Score bands, sample sizes, and unavailable counts inform interpretation without certifying reliability. See [report diagnostics](source/reference/reports.md) and the independent [data diagnostics](source/data-diagnostics.md) path.

Target-specific checks apply to MLE; ordinary distribution metrics need no target declaration.

## Statistical failure modes

| Failure mode | What can go wrong | How TabGenEval handles it |
|---|---|---|
| <a id="sample-size-dependence"></a> Sample-size dependence | comparisons drift with `n` (KS, PRDC) | match paired comparisons at the uncertainty mode's resolution using metric-eligible source counts; fixed/reference modes use `min(n_generated, n_holdout//2)`, while both mode uses `n_holdout//2` if `n_generated > n_holdout//2` and `n_generated//2` otherwise; MLE matches its two training pools and shared scoring pool — see [data roles and resolution](source/methodology.md#data-roles-and-resolution) |
| <a id="duplicate-ideal-inflation"></a> Duplicate-inflated NN ideal | reusing source observations across real-real roles creates artificial zero-distance matches | use disjoint source positions for the two real roles within every fixed or repeated comparison; make all eligible rows available again for later draws |
| <a id="ratio-instability"></a> Ratio instability near zero | small reference frequencies amplify recovery ratios; unsupported ratios become undefined | recovery includes only slices meeting the real minimum-count rule; safe division leaves zero/nonfinite-denominator ratios undefined; aggregate means and empirical bands use finite outcomes and retain unavailable counts |
| <a id="zero-dcr-baseline"></a> Zero DCR baseline | a zero holdout-to-training nearest-distance median makes the ratio undefined, including `0/0` | flag only the ratio with `ZERO_BASELINE`; retain valid raw medians and do not add an epsilon |
| <a id="mismatched-calibration-geometry"></a> Mismatched comparison geometry | independently fitted scales or references make a closest-record ratio incomparable | use separate actual-training memorization geometry and MLE training/test roles; record the fitted geometry and per-replicate ratio inputs |
| <a id="boundary-saturation"></a> Boundary saturation | repeated scores pinned at a boundary produce a zero-width empirical band | report the observed band and compare with real-real variation; no automatic reliability judgment |
| <a id="degenerate-columns"></a> Undefined stats on degenerate columns | constant columns make correlations undefined; a column can have no observed values | exclude undefined column/pair scores from aggregate means; if none remain the aggregate is unavailable with diagnostics; constant-column KS comparisons remain valid |
| <a id="high-cardinality-categoricals"></a> High-cardinality categoricals | a huge-cardinality column would blow up PRDC's one-hot distance matrix (memory ∝ rows × total levels) | use compact category codes when needed to preserve the same distances without a wide one-hot observation matrix; observation storage scales with columns while vocabulary metadata still depends on levels; unknown reference-vocabulary categories retain the documented all-zero encoding; fuzz- and equivalence-tested |
| <a id="distance-boundary-rounding"></a> Distance-boundary rounding | coordinate rounding or square-root arithmetic changes strict PRDC membership at tied distances | tensor kernels retain selected FP32/FP64 from source conversion through direct squared-distance comparisons; Python PRDC uses requested coordinate precision and float64 squared-distance comparisons. Strict `<` boundaries are checked against independent oracles, duplicates/category ties and replicate parity; FP32 rounded boundaries can differ from FP64 |
| <a id="discrete-ks-ties"></a> Discrete data / KS ties | ties and finite sample sizes change the distribution of KS scores | compute a matched real-real reference on the same type of data to provide finite-sample context; this is not a general bias correction |
| <a id="subpopulation-association-collapse"></a> Subpopulation association collapse | global Shape/Trend look fine while structure breaks *within* subpopulations (Simpson-style) | Conditional metrics score Shape/Trend/Recovery within slices, average equally within each conditioning column, then average equally across columns; rare companions expose retained rare slices |
| <a id="ci-undercoverage"></a> Score-band tail resolution | few repetitions give noisy quantiles, and a central score band can be mistaken for a confidence interval for the population mean | expose raw repeated scores, finite counts and empirical quantiles; describe bands as score variability and explicitly disclaim confidence-interval interpretations for population expected scores |
| <a id="preprocessing-leakage"></a> Preprocessing leakage | fitting encoders/scalers on scoring data leaks scoring information into the fit | classifier transforms fit training partitions only; MLE uses disjoint real training/scoring samples within each comparison; distance encoders fit the reference side |
| <a id="classifier-optimization-failure"></a> Classifier training failure | an unconverged logistic model or failed tree fit can produce a misleading result | retain finite nonconverged scores with termination diagnostics; exclude nonfinite scores with counts and reasons; engine failures remain visible |
| <a id="multiple-comparisons"></a> Multiple comparisons | reporting many metrics × models inflates false "significant" gaps | retain raw scores and descriptive bands without automatic significance decisions or a p-value guarantee |

## Engineering / "in the wild" failure modes

| Failure mode | What can go wrong | How TabGenEval handles it |
|---|---|---|
| <a id="wrong-input-type"></a> Wrong input type | a non-`EvalData` argument or non-DataFrame source pool | raise an actionable type/validation error naming the expected input and offending role |
| <a id="column-mismatch"></a> Column-set mismatch | extra / missing / renamed columns | raise with an explicit set-diff; column *order* differences are tolerated (align by name) |
| <a id="dtype-coercion"></a> Dtype mismatch / numbers-as-strings | a column is float in one frame, string in the other; `"25"` instead of `25` | numeric roles require numeric storage and reject text; the caller must convert deliberately; categorical identities remain unchanged |
| <a id="nan-inf-handling"></a> NaN / ±inf | NaN or `±inf` in either frame | numeric infinities raise; genuine missing values follow metric-specific contracts; distance complete-case and MLE target eligibility precede sampling and record source exclusions; exhausted pools leave affected scores unavailable with eligibility diagnostics |
| <a id="degenerate-sizes"></a> Degenerate sizes | 0/1 row, 1 column, empty after missing-value exclusions | validation raises on truly empty inputs; preserve computable tiny-sample statistics and mark unsupported ones unavailable or `NOT_APPLICABLE`, without an index error |
| <a id="size-extremes"></a> Size extremes / huge frames | `n_generated ≫ n_holdout` or `≪`; very large frames | paired comparisons use the automatic resolution of their eligible pools; memorization retains all eligible actual-training/query rows without volume matching; report source sizes and bound pairwise storage |
| <a id="duplicate-rows"></a> Duplicate rows in inputs | the generated set emits many identical rows | distributional metrics tolerate them; NN/overlap metrics reflect them as real signal; independent data diagnostics report the duplicate rate |
| <a id="constant-columns"></a> Constant / zero-variance columns | a column is constant in holdout and/or generated | range-scale divisor → 1.0; undefined correlations are excluded; KS remains defined, with identical constants scoring 1 and distinct constants scoring 0 |
| <a id="category-alignment"></a> Category alignment / unseen levels | generated levels absent from holdout; label coercion merges distinct categories | typed identities preserve scalar families and exact strings; metric-specific encoders preserve their documented unknown-category treatment without fitting on scoring rows; independent `diagnose` checks generated support against actual training data |
| <a id="temporal-and-unsupported-dtypes"></a> Temporal / unsupported dtypes | datetime/timedelta/period; complex/interval/nested objects | temporal measurements require explicit numeric conversion and units or an intentional categorical role; unsupported representations raise `ValidationError` asking the user to convert or exclude the column |
| <a id="unicode-categories"></a> Unicode / weird category strings | emoji, newlines, NUL, very long strings | treated as opaque labels; never `eval`/format-injected; output rendering escapes them |
| <a id="index-misalignment"></a> Index misalignment | non-default / non-unique `DataFrame.index` | select and compare records by row position; index labels do not align records across roles |
| <a id="target-column"></a> Target column problems | missing declaration, absent column, missing labels, or unsupported classification classes | MLE requires an explicit `Schema.target` and excludes it from predictors; missing targets are dropped; unsupported classification classes give undefined scores with diagnostics; regression MAE supports constant truth and one scoring row |
| <a id="non-determinism"></a> Non-determinism | unseeded randomness | a master seed spawns child RNGs throughout; a determinism test pins it |
| <a id="multiprocessing"></a> Parallelism hazards | races / non-determinism when work runs concurrently | compiled CPU owns immutable buffers and restores local thread budgets; CUDA draws execute sequentially on the caller stream. Seeded batches preserve replicate order and serial/parallel parity. Python/custom metrics retain joblib processes. |
| <a id="hostile-payloads"></a> Hostile / malformed payloads | random dtypes, all-NaN, 1×1, pathological floats | the fuzz suite asserts the dichotomy: a flagged `Report` or a typed error, never an uncaught crash |
| <a id="config-dos"></a> Memory/time DoS via workload | very large replicate counts or source inputs | validate evaluation options; automatic memory planning and bounded distance storage |
| <a id="unsupported-execution"></a> Unsupported execution | an explicit device or precision request silently runs a different kernel | validate execution options, raise for unavailable CUDA or unimplemented metric precision/device combinations, and record the actual frontend/kernel/device/dtype |
| <a id="tensor-dependency-failure"></a> Tensor dependency failure | missing PyTorch or a broken installed binary breaks default execution | automatic selection uses Python when the top-level Torch dependency is absent and device/precision retain automatic FP64 defaults; broken installed imports and explicit tensor requests raise. Explicit Python and custom contracts remain independent |
| <a id="workload-routing-mismatch"></a> Workload routing mismatch | automatic routing ignores workload, minimum storage or framework requirements | Torch routing uses effective draw sizes and conservative work estimates; small tensor workloads stay CPU; XGBoost auto checks its GPU engine, CuPy bridge and workspace before preferring CUDA; unavailable dependencies or insufficient workspace route CPU; explicit device requests remain enforced and decisions are recorded |
| <a id="tensor-binary-incompatibility"></a> Tensor binary incompatibility | an incompatible Torch/CUDA/CPU/source library loads or corrupt binary data is accepted | automatically discovered artifacts validate exact Torch build, C++ ABI, platform, source digest, SHA256 and minimum GLIBC before loading; GLIBCXX requirements are recorded and enforced by the dynamic linker; incompatible artifacts use source fallback; binary wheels pin their Torch distribution version and runtime metadata verifies the full build |
| <a id="triton-host-bundle-mismatch"></a> Triton host bundle mismatch | wrong Python/Triton/source ABI or corrupt host modules enter the launcher cache | matched CUDA artifacts validate Python SOABI, Triton/source identity, GLIBC and every checksum before seeding Triton's standard cache; changing cache roots reseeds compatible modules; device JIT/compiler hooks remain unchanged |
| <a id="tensor-source-corruption"></a> Tensor source corruption | aliasing caller data, changing duplicate multiplicities, or accepting invalid row indices corrupts draws | owned preparation/transfers, integer index validation, order- and duplicate-preserving gathers, unchanged NumPy seeds and fixed folds |
| <a id="gpu-workspace-overflow"></a> GPU workspace overflow | gathered draws, kernel tiles or concurrent sampling buffers exceed the temporary device budget | reserve draw/index/geometry/reduction state before gathering, tile both axes, and release draw-local tensors before the next task; reject oversized tasks; automatic planning reserves pending input storage and runtime headroom |
| <a id="tensor-distance-precision-loss"></a> Tensor distance precision loss | FP64 geometry passes through FP32, ambient autocast changes arithmetic, or approximate boundaries corrupt scores | preserve the selected dtype from source conversion through scaling/distances/medians; use direct differences and strict comparisons with exact integer category counts; independently validate both precisions |
| <a id="tensor-fidelity-semantic-drift"></a> Tensor fidelity semantic drift | whole-row filtering replaces pairwise missingness, bin boundaries change, or high cardinality densifies a huge joint grid | preserve per-pair finite cells, reference-fitted right-closed quantile bins and typed categorical identities, including observed literal `"nan"`; exact integer counts, bounded dense grids and occupied-cell sparse reductions; independent per-pair and full-report tests |
| <a id="tensor-classifier-semantic-drift"></a> Tensor classifier semantic drift | preprocessing leaks across source folds, compact one-hot changes feature meaning, or numerical failures disappear | training-only transforms and fixed source identities; full one-hot implicit forward/adjoint and full Hessian operators; stable selected-precision objective differences, unchanged ridge/tolerances and reported direction damping/preconditioner/failures |
| <a id="float-reproducibility"></a> Float reproducibility across platforms | distances differ in last ULPs across BLAS/OS | tests compare with tolerances (`np.allclose`), never exact equality |

## Exact memorization search

DCR uses exact nearest-record search on every supported backend.
