[TabGenEval](https://github.com/granica-ai/tabgen-eval/) is a **comprehensive, high-performance package** for evaluating synthetic tabular
data generated by **tabular generative models**, using real data as the reference. Its evaluation framework is
organized around three core pillars: **Fidelity, Memorization, and Utility**.

TabGenEval offers four key features: (1) comprehensive population- and subpopulation-level evaluations, (2) real-data references, (3) uncertainty quantification, and (4) high-performance evaluation.


## Comprehensive evaluation

::::{grid} 1 1 3 3
:gutter: 3
:class-container: ltm-home-dimensions

:::{grid-item-card} Fidelity
:link: metrics/index
:link-type: doc

Synthetic data should preserve the statistical structure of real data. The fidelity pillar measures how closely synthetic data match an independent real holdout, from individual columns and their correlations to subpopulations and local geometry.

Shape · Trend · Conditional Fidelity · PRDC · C2ST · Concentration
:::

:::{grid-item-card} Memorization
:link: metrics/memorization/index
:link-type: doc

Memorizing training data can inflate fidelity scores, indicate overfitting, and increase privacy risks. The memorization pillar measures the extent to which synthetic data reproduce training records.

DCR · Near-match Rate · Replication Ratio
:::

:::{grid-item-card} Utility
:link: metrics/utility/index
:link-type: doc

Synthetic data should maintain predictive power. The utility pillar measures how models trained on synthetic data compare with models trained on real data, using an independent real test set to assess predictive performance.

MLE · Prediction Agreement
:::
::::

## Give each score a reference

Finite-sample variability introduces uncertainty into evaluation scores. TabGenEval provides real-vs.-real references and uncertainty quantification for all metrics at the same sample size as the synthetic-vs.-real comparison, enabling meaningful interpretation of the observed scores.

## Fast evaluation on CPU and GPU

Some evaluation metrics are computationally expensive, with quadratic complexity in sample size. To enable efficient evaluation of large, high-dimensional tables, TabGenEval leverages optimized CPU operators (compiled C++/ATen) and GPU kernels (compiled CUDA/Triton). Compared to equivalent Python CPU implementations, these optimized CPU and GPU routines achieve 33.4x and 90.8x speedups, respectively, reducing evaluation time to a few seconds.

:::{container} ltm-home-latency

```{raw} html
:file: _generated/landing/speedup.html
```

*Across five datasets and four sample sources, average evaluation latency was
233.35 seconds for Python CPU, 6.99 seconds for optimized CPU, and
2.57 seconds for GPU per computation -- approximately a 33.4x speedup on
optimized CPU and a 90.8x speedup on GPU relative to Python CPU in this benchmark.*
